# 小红书账号运营

把账号运营视为可验证的闭环：定位 -> 研究 -> 选题 -> 制作 -> 审核 -> 发布 -> 互动 -> 复盘。优先稳定产出和真实价值，不追求无边界的自动互动。

## 首次运行

1. 读取 [references/account-profile.md](references/account-profile.md)。
2. 检查当前项目中的 `.agents/product-marketing.md`、品牌资料、产品事实、历史内容和指标文件；存在时先读取，不重复询问。
3. 若账号档案仍有关键占位符，只询问会改变结果的最少问题：账号定位、目标受众、商业目标、可验证事实、发布权限。
4. 把用户回答写回账号档案前先说明将保存哪些信息；用户未要求持久化时，仅在当前任务中使用。
5. 需要规划指标或记录数据时，读取 [references/metrics.md](references/metrics.md)。
6. 需要选题时读取 [references/topics.md](references/topics.md)；需要写笔记、改写或润色时同时读取 [references/writing-craft.md](references/writing-craft.md)、[references/writing-phrases.md](references/writing-phrases.md) 和 [references/templates.md](references/templates.md)；需要合规检查或准备发布时读取 [references/compliance.md](references/compliance.md)。

缺少真实经历、立场或原创素材时，可以先生成带占位符的结构草稿，并把缺口列为发布前确认项；不得代替用户编造事实。

## 决策路由

- 用户要账号定位或长期规划：输出 3-5 个内容支柱、受众问题、内容比例、30 天验证目标。
- 用户要选题：读取 [references/topics.md](references/topics.md)，结合账号档案、历史表现和近期可核实信息，生成候选池并评分。
- 用户要写笔记、改写或润色：读取 [references/writing-craft.md](references/writing-craft.md)、[references/writing-phrases.md](references/writing-phrases.md) 和 [references/templates.md](references/templates.md)，先确认事实与作者声音，再交付完整发布包，不只给正文。
- 用户要发布：读取 [references/compliance.md](references/compliance.md) 并完成发布门禁，再使用已授权的结构化工具；没有结构化工具时才使用浏览器自动化。
- 用户要互动：先分类，再为低风险 FAQ 起草或按白名单回复；争议、投诉、交易和隐私问题转人工。
- 用户要复盘：读取真实数据，区分事实、推断和下一轮实验，不把单篇波动当成长期规律。

## 账号策略

1. 定义一个主要商业目标和一个主要受众动作，避免同时优化所有指标。
2. 建立 3-5 个内容支柱，每个支柱同时满足：受众关心、账号有可信表达空间、能够持续生产。
3. 将内容分为：
   - 搜索型：回答明确问题，标题贴近用户搜索表达。
   - 分享型：提供新观点、清单、案例或可保存的模板。
   - 信任型：展示过程、证据、经验边界和真实限制。
   - 转化型：自然连接产品或服务，避免生硬推销。
4. 默认建议价值内容占多数，转化内容保持克制；最终比例以账号档案和历史数据为准。
5. 只把可验证的高表现结构当作参考，不复制他人的文字、图片、人设或未经授权素材。

## 选题工作流

1. 收集四类信号：受众问题、搜索意图、历史表现、近期趋势。
2. 为每个候选题按 1-10 分评分：
   - 受众价值 35%
   - 账号匹配 25%
   - 分享或收藏潜力 20%
   - 主要目标相关性 10%（商业账号可具体解释为转化相关性）
   - 制作成本 10%（成本越低分越高）
3. 去除近 30 天重复角度；如要复用旧题，必须改变受众、场景、证据或内容格式。
4. 选定一个主选题和两个备选题，说明选择依据和需要验证的假设。
5. 对时效性、产品价格、政策或第三方数据进行实时核实；无法核实时明确标注，不编造。

## 笔记发布包

按 [references/writing-craft.md](references/writing-craft.md) 完成素材盘点、结构选择、初稿和四层自检，使用 [references/templates.md](references/templates.md) 选择完整骨架，再从 [references/writing-phrases.md](references/writing-phrases.md) 按账号语气挑选少量话术。模板和话术服务于真实内容，不反过来编造经历填满模板。

每篇内容至少输出：

1. 目标：受众、用户动作、所属内容支柱。
2. 标题：3 个方向不同的候选标题，避免虚假紧迫感和无法证明的承诺。
3. 正文：开头钩子、主体价值、证据或例子、自然 CTA。
4. 标签：只保留与内容直接相关的标签，不堆砌热门词。
5. 视觉：封面文案、3:4 或当前发布界面要求的画幅建议、配图清单和生成提示词。
6. 合规结果：事实来源、潜在风险、需要人工确认的表述。
7. 发布计划：建议时间、发布模式、发布后首轮检查时间。

账号事实不足时，正文中的个人经历、地点、价格、立场和效果只能使用显式占位符，不能把示例当成用户事实。

需要生成位图封面或配图时调用 `imagegen`；先使用用户品牌资产和原创素材。不得生成冒充真实客户、伪造效果对比、虚构聊天记录或无依据证书的图片。

## 发布门禁

发布前读取 [references/compliance.md](references/compliance.md)，对完整发布包逐项确认。词语匹配只用于发现风险，最终判断必须结合上下文；规则、政策或平台界面可能变化时，以当前官方信息为准。

逐项确认：

- 标题、正文、图片、标签和 CTA 已组成不可再变的发布包。
- 产品功能、价格、数据、案例和引述均有来源或被明确标注为个人经验。
- 未包含隐私信息、未授权肖像、侵权素材、绝对化承诺或隐藏广告关系。
- 内容没有复制竞品或创作者的独特表达。
- 当前发布模式允许此次操作。

发布模式：

- `draft-only`：默认。只在当前任务中生成材料；不进入网站、不写入平台草稿、不发布。
- `confirm-before-publish`：任何网站写入都需获得本次明确确认。保存平台草稿不等于获准发布；点击发布前必须再次确认。
- `allowlist-auto`：仅当账号档案明确列出可自动发布的内容类型、频率上限和停止条件时使用。

执行发布时：

1. 优先使用账号获准使用的官方或结构化接口。
2. 需要网页操作时使用 `agent-browser`，先检查登录状态和当前页面，再上传并填写。
3. 发布前再次读取页面中的最终标题、正文、图片数量和账号身份。
4. 发布后保存链接、时间、最终内容和成功证据。
5. 遇到验证码、二次认证、登录异常、风控提示、页面结构变化或重复发布风险时立即停止，通知用户人工接管；不得尝试绕过。

## 互动和评论

把评论分为四类：

- FAQ：依据已核实资料回复。
- 正向互动：简短、具体、避免模板化刷屏。
- 商业咨询：回答公开信息；涉及报价、订单或个人资料时转私域或人工。
- 投诉、争议、法律、医疗、财务及安全问题：不要自动回复，整理上下文并升级人工。

不得自动批量关注、点赞、收藏、复制评论或发送未经请求的私信。自动回复只适用于账号档案中明确批准的 FAQ 白名单，并遵守频率上限。

## 复盘循环

1. 按 [references/metrics.md](references/metrics.md) 记录实际数据。
2. 每周比较同一内容支柱和同一格式，避免把不同样本强行比较。
3. 找出表现最好的 3 篇和最弱的 3 篇，分别分析标题、主题、视觉、发布时间和 CTA。
4. 只提出最多 3 个下一轮实验，每个实验只改变一个主要变量。
5. 记录结论的置信度：高（多次复现）、中（有趋势）、低（单篇观察）。
6. 不因短期曝光波动自动大幅改变账号定位。

## 输出格式

根据任务返回最小必要结果，并始终包含：

- 当前目标
- 已完成内容或操作
- 证据与风险
- 下一步及是否需要人工确认

执行了外部发布或回复时，必须附上结果链接或可核验凭据；未成功时明确说明停在哪一步，不把草稿或页面填写完成描述为已发布。
