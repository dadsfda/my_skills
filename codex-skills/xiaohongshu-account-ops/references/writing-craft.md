# 小红书内容写作方法

本文件用于写笔记、改写、润色和终审。目标是把真实素材组织成易读、有用、有作者声音的内容，不模仿特定博主，也不以固定口癖、emoji 数量或夸张承诺制造“平台感”。

## 1. 人与 AI 的分工

作者负责提供或确认：

- 第一手经历、真实判断、情绪变化和不确定性。
- 价格、时间、地点、人物关系、使用周期等事实。
- 原创素材、授权情况、是否存在商业合作。
- 哪些表达符合本人，哪些虽然顺口但不像自己。

AI 可以负责：

- 从素材中提炼角度，比较多种结构。
- 优化标题、开头、段落顺序和阅读节奏。
- 把抽象观点改成步骤、清单、场景或判断标准。
- 标注事实缺口、生成配图 brief、执行合规与质量检查。

AI 不得代写成用户“亲测过”、虚构对话、捏造情绪或补造生活细节。材料不足时使用显式占位符，例如 `[补充真实使用周期]`。

## 2. 写作前素材单

动笔前尽量收齐六项：

```text
想让谁看：
想解决什么问题：
我的核心判断：
支持判断的真实细节：
限制、缺点或反例：
希望读者看完做什么：
```

真实细节优先于形容词。优先收集可观察信息：一次具体场景、一个动作、一个数字及口径、一张原创图片、一次选择与后果。

缺少核心判断或第一手证据时，先输出采访问题或结构草稿，不生成“可直接发布”的体验叙述。

## 3. 内容价值快筛

从三个维度检查选题是否值得写：

- **吸引力**：标题和首图能否让目标读者迅速理解冲突或结果，而不是只靠夸张词。
- **可获得价值**：读者能否学到一个动作、标准、清单、路线或避坑点。
- **共鸣与讨论**：是否存在真实处境、选择成本或可分享的经验。

三项都有可优先制作；只有两项时补强薄弱项；只有一项时重新找角度。这里是创作快筛，不替代 `topics.md` 的正式评分，也不代表流量预测。

## 4. 六步写作流程

### 第一步：写一句内容承诺

用一句内部工作句限定文章：

`给[人群]在[场景]下一个关于[问题]的可验证判断或做法。`

正文中不一定出现这句话，但每一段都应服务于它。

### 第二步：选择内容原型

根据证据类型选择体验报告、诚实推荐、场景洞察、教程攻略或经验清单。没有第一手体验时，不选体验报告或诚实推荐。

### 第三步：先排证据，再写观点

先列出“主张 → 证据 → 边界”：

```text
我想说什么：
哪条真实细节支持它：
在哪些情况下不成立：
```

不能找到证据或边界的主张，应删除、降级为问题，或明确标为个人猜测。

### 第四步：写开头

从以下入口选一个，不机械叠加：

- **问题入口**：指出一个具体麻烦，避免泛泛问“你是不是也”。
- **结果入口**：先给有限结论，再交代适用范围和过程。
- **身份入口**：只使用真实且与判断有关的身份信息。
- **意外入口**：写真实反差，不用“震惊”“封神”替代内容。
- **现场入口**：用一个可验证瞬间带出主题，保护他人隐私。

开头的任务是让读者知道“这篇和我有什么关系”，不是把结果吹到最大。

### 第五步：推进正文

- 每个段落只承担一个主要意思。
- 先写结论，再写依据；复杂教程按动作顺序展开。
- 每个主要观点至少配一个场景、步骤、数字、对比标准或失败点。
- 对比内容使用同一口径，同时写优点、缺点和适合人群。
- 把作者感受与可验证事实分开表达。
- 删除不推动理解的重复铺垫和空泛升华。

### 第六步：自然收束

结尾优先选择一种：

- 总结适合谁、不适合谁。
- 给出下一步可执行动作。
- 承认仍未解决的问题。
- 提出需要经验才能回答的具体问题。

不设置点赞数量门槛，不要求“扣 1”或只回复字母，不把关注收藏作为交换条件。

## 5. 五类内容原型

### 体验报告

结构：有限结论 → 使用场景与周期 → 关键发现 → 缺点与边界 → 适用建议。

核心证据：本人使用过程、原始记录、实拍或可核实结果。

### 诚实推荐或劝退

结构：关系披露 → 评价标准 → 优缺点及场景 → 适合与不适合的人 → 购买前检查。

核心证据：购买/借用/赠送关系、版本与价格日期、统一比较标准。

### 场景洞察

结构：具体现场 → 发生了什么 → 为什么值得注意 → 可复用判断 → 开放问题。

核心证据：真实观察。涉及他人时匿名化，不替他人编造心理活动。

### 教程攻略

结构：适用条件 → 准备项 → 顺序步骤 → 结果检查 → 常见失败与补救。

核心证据：实际走通过程、界面或路线版本、错误处理。

### 经验清单

结构：筛选标准 → 分组清单 → 每项理由与限制 → 优先级 → 遗漏项征集。

核心证据：为什么入选、为什么排除，而不是堆数量。

## 6. 语言与节奏

- 使用自然口语，但不要强塞“家人们”“绝了”等不符合账号的口癖。
- 以短句和短段为主；长句能清楚表达时无需强行拆碎。
- 先删“在当今时代”“众所周知”“首先其次最后”等模板化铺垫。
- 把“非常好用”“提升幸福感”“高性价比”改成具体场景和判断标准。
- emoji 只用于情绪或分区，数量取决于账号风格；可以不用，不堆叠，不替代文字。
- 身份标签只在能解释经验边界时出现，不反复强调人设。
- 保留适量不完美：犹豫、失败、限制和个人偏好往往比全是优点更可信。
- 不为了“金句”牺牲准确性；自然结论优先于强行升华。

## 7. 图文互证

先确定每张图要证明什么：

- 首图：让读者识别主题、场景或核心选择。
- 过程图：证明步骤、使用环境或时间顺序。
- 对比图：使用相同角度、条件和口径；不得伪造效果。
- 信息图：帮助保存和复用，不重复整段正文。
- 收束图：总结清单或提出具体讨论问题。

文字负责解释背景、判断与限制，图片负责呈现事实或过程。若图片不能支持正文主张，修改主张或更换素材，不靠图注文案制造证据。

## 8. 四层自检

### 第一层：事实与安全

- 每个经历、数据、价格、功能、引述和合作关系是否真实可追溯。
- 是否把个人体验写成普遍结论，或遗漏重要限制。
- 是否存在隐私、肖像、版权、医疗功效、绝对化承诺或引流风险。

### 第二层：结构与可读性

- 标题、首图和正文是否承诺同一件事。
- 前两段是否说明对象、问题或结果。
- 段落顺序是否自然，每段是否只有一个主要意思。
- 删掉一段后若不影响理解，该段通常应删除。

### 第三层：价值与证据

- 读者能否带走至少一个具体判断、动作、标准或清单。
- 核心观点是否有细节支持，图文是否互证。
- 教程能否执行，测评能否复核，清单是否说明筛选理由。

### 第四层：作者声音

- 这像本人分享，还是通用营销稿或 AI 套话。
- 是否保留真实偏好、限制和不确定性。
- 口癖、emoji、身份标签和幽默是否自然。
- 评论问题是否只有目标读者凭经验才能回答。

任一层失败时先修改正文，再重新检查；不要只输出问题清单而保留有风险的“最终稿”。

## 9. 交付格式

在完整发布包中增加简短写作质检：

```text
结构原型：
核心判断：
使用的真实证据：
仍需补充的事实：
事实与安全：通过 / 条件通过 / 停止
结构与可读性：通过 / 需修改
价值与证据：通过 / 需修改
作者声音：通过 / 待本人确认
```

只报告会影响发布的主要问题，不输出冗长的形式化打分。
